## 2. Decisões tomadas

1. **Seletor de Amanda mantido.** O RF-004 acrescentou: o código do tipo em cada opção (`data-code`), uma ajuda, o botão da explicação, a caixa de exigências e o nome do botão "tentar de novo" para leitor de tela. Os `id`s que ela usa não mudaram.
2. **Tudo do RF-004 num arquivo próprio** (`includes/classificacao_mudanca.html`), no mesmo padrão do `secao_referencia.html` do RF-003: marcação, CSS e o objeto JavaScript `ClassificacaoMudanca`.
3. **Explicações com os textos do BDA.** O back não tem descrição dos tipos; o time de BDA já tinha escrito uma para cada um. Usei esses textos, em vez de inventar.
4. **Exigências pelo código do tipo, não pelo nome.** O nome pode ser trocado pelo administrador; o código não. Se alguém renomear "Crítica", a tela continua certa, e a explicação mostra o nome novo.
5. **Antes de salvar, a tela mostra o que o back vai aplicar; depois de salvar, mostra o que o back aplicou.**
   - Antes de salvar, vale a mesma regra do back ("Exigências do tipo X … Serão aplicadas ao salvar o rascunho").
   - Depois de salvar ou ao reabrir, vêm os dados do próprio back (`required_flags`, "Exigências aplicadas a esta mudança").
   - Isso respeita um detalhe do back: se o tipo não muda, ele **mantém** as exigências já gravadas.
6. **Explicação recolhível** (Bootstrap *collapse*), aberta pelo botão "Entenda os tipos de mudança" logo abaixo do campo. Fica fechada para não alongar o formulário. Foi escolhida em vez de *tooltip*/*popover*, que funcionam mal no celular e no leitor de tela.
7. **A explicação mostra só os tipos que podem ser escolhidos.** Um tipo desativado sai da lista e da explicação. Se a lista não carregar, a explicação mostra os quatro.
8. **Proteção do tipo salvo.** Enquanto a lista de tipos está carregando ou falhou, o tipo salvo vai num campo oculto. Assim salvar não o apaga. Quando a lista volta ("tentar de novo"), o tipo salvo é marcado de novo.

## 5. Como ficou o fluxo

1. **Campo "Tipo de Mudança"** (nas telas nova e de edição): logo abaixo há a ajuda "Cada tipo define as exigências que o sistema aplica à mudança", o botão **"Entenda os tipos de mudança"** e a caixa de exigências.
2. **Sem tipo escolhido:** "Selecione um tipo para ver as exigências que o sistema aplica."
3. **Escolheu um tipo:**
   - a caixa mostra "Exigências do tipo Crítica: • Controles adicionais — Serão aplicadas ao salvar o rascunho. Os dados já preenchidos são mantidos.";
   - o leitor de tela anuncia o mesmo;
   - na explicação, o tipo fica marcado como "✓ Selecionado".
4. **Salvou (ou reabriu):** "Exigências aplicadas a esta mudança", com o que o back gravou.
5. **"Entenda os tipos de mudança":**
   - abre, dentro do formulário, os quatro tipos com descrição e exigências;
   - fecha pelo próprio botão ou pelo "×".
6. **Enviar sem tipo:** "Este campo é obrigatório." junto ao campo, com o foco nele.
7. **Tipo desativado pelo administrador:**
   - some da lista para novas escolhas;
   - numa mudança que já o usa, aparece como "Crítica (Desativado)", com o aviso de Amanda e as exigências gravadas.
8. **Lista de tipos fora do ar:**
   - aviso e botão "tentar de novo" (de Amanda);
   - salvar não apaga o tipo salvo;
   - ao recarregar, o tipo volta marcado.
